# Интеграция с Immich (my.rybnikov.su)

| Поле             | Значение                                                              |
| ---------------- | --------------------------------------------------------------------- |
| Тип документа    | Справочник по внешнему сервису + план интеграции (не модульная спека) |
| Сервис           | [Immich](https://immich.app/) — self-hosted медиатека (фото/видео)    |
| API-документация | https://api.immich.app/                                               |
| Статус           | Актуально (соответствует текущему коду)                               |

Immich — self-hosted фото/видео-медиатека (аналог Google Photos). Семейный инстанс уже
подключён в футере портала как «Архив». Цель интеграции — использовать Immich для
фотографий в событиях «Дневника» (и в перспективе — общая семейная медиатека).

> Это справочный документ о внешнем API и плане интеграции. Функциональные требования
> модулей приложения живут в модульных спецификациях (`docs/specification-*.md`), API
> приложения — в `docs/specification-api.md`.

---

## 1. Аутентификация в Immich API

Большинство эндпоинтов требует аутентификации. Схемы (из документации https://api.immich.app/authentication):

| Схема         | Как передаётся                                     | Назначение                                    |
| ------------- | -------------------------------------------------- | --------------------------------------------- |
| **API-ключ**  | Заголовок `x-api-key: <key>` или query `?apiKey=`  | Для 3rd-party приложений; тонкие права        |
| Session-токен | `x-immich-user-token` / `x-immich-session-token`   | Привязан к сессии пользователя (полные права) |
| Shared link   | `x-immich-share-key`/`slug` или query `key`/`slug` | Публичный доступ к конкретному альбому/набору |

### 1.1. Права API-ключа для интеграции

Требуемые права зависят от используемых операций (по документации https://api.immich.app/permissions):

| Назначение                                | Эндпоинт Immich                           | Право (permission) |
| ----------------------------------------- | ----------------------------------------- | ------------------ |
| Проверка соединения (шаг 1)               | `GET /server/about`                       | `server.about`     |
| Поиск фото для пикера (по дате/альбому)   | `POST /search/metadata`                   | `asset.read`       |
| Миниатюры в пикере                        | `GET /assets/{id}/thumbnail`              | `asset.view`       |
| Скачивание оригинала (импорт в событие)   | `GET /assets/{id}/original`               | `asset.download`   |
| Список альбомов (фильтр «по альбому»)     | `GET /albums`                             | `album.read`       |
| Загрузка ассета (вариант C — зеркало)     | `POST /assets`                            | `asset.write`      |
| Создание альбома / добавление (вариант C) | `POST /albums`, `PUT /albums/{id}/assets` | `album.write`      |

**Минимальный набор для шага 1 + варианта B2 (пикер-импорт):** `server.about`, `asset.read`,
`asset.view`, `asset.download`. `album.read` — только если нужен фильтр по альбомам (можно начать
с фильтра по диапазону дат). `GET /server/version` и `/server/ping` — публичные, прав не требуют.
Для «зеркала» (вариант C) дополнительно `asset.write` + `album.write`.

Нюансы: `asset.view` (превью) ≠ `asset.download` (оригинал) — запрос полного размера превью может
редиректить на `downloadAsset` (тогда нужен и `asset.download`); в пикере достаточно маленького
превью. Скоупы задаются при создании ключа в настройках пользователя Immich; обычный ключ без
ограничений = полные права пользователя (для семейного self-hosted приемлемо).

**Рекомендация для интеграции:** API-ключ пользователя (`x-api-key`), создаётся в
настройках пользователя Immich (User settings → API Keys). Ключ хранится **только на
бэкенде** (в БД настроек, см. §4), на фронтенд не отдаётся — все вызовы Immich идут
через бэкенд-прокси под авторизацией портала.

API-ключи поддерживают scoped-права (ограничение по набору permission); по умолчанию —
полные права пользователя. При выдаче ключа для интеграции стоит минимизировать права,
если это требуется сценарием.

## 2. Ключевые группы эндпоинтов (https://api.immich.app/endpoints)

### 2.1. Server (диагностика/проверка соединения)

| Метод | Путь              | Назначение                               | Требует auth |
| ----- | ----------------- | ---------------------------------------- | ------------ |
| GET   | `/server/ping`    | `{res: 'pong'}` — живо ли API            | нет          |
| GET   | `/server/version` | `{major, minor, patch}` — версия сервера | нет          |
| GET   | `/server/about`   | инфо о сервере (включая версию)          | **да**       |

`GET /server/about` — каноническая проверка «адрес + API-ключ» (200 при валидном ключе,
401 — неверный ключ). Используется в проверке соединения из админки (шаг 1, §4).
**Формат ответа зависит от версии Immich:** старый — объект `serverVersion {major, minor, patch}`;
новый (DTO v2) — строка `version` (например `"3.1.0"`). Парсер в `immichService.ts` понимает
оба формата, при отсутствии версии в ответе добирает её из публичного `/server/version`.

### 2.2. Assets (фото/видео)

| Метод | Путь                          | Назначение                               |
| ----- | ----------------------------- | ---------------------------------------- |
| POST  | `/assets`                     | Загрузка ассета (multipart)              |
| GET   | `/assets/{id}/thumbnail`      | Готовый превью (для списков/галерей)     |
| GET   | `/assets/{id}/original`       | Оригинал файла (полное разрешение)       |
| GET   | `/assets/{id}/video/playback` | Видео для плеера                         |
| GET   | `/assets/{id}`                | Инфо об ассете (метаданные, EXIF и т.п.) |
| GET   | `/assets/statistics`          | Статистика                               |
| POST  | `/assets/bulk-upload-check`   | Проверка «уже загружен/нет» (дедуп)      |

Ассет — это изображение или видео, загруженное в Immich. Thumbnail отдаётся сервером
готовым (аналог нашего ленивого превью `?preview=1` в «Дневнике»).

### 2.3. Albums (альбомы)

| Метод  | Путь                  | Назначение                        |
| ------ | --------------------- | --------------------------------- |
| GET    | `/albums`             | Список альбомов                   |
| POST   | `/albums`             | Создать альбом                    |
| GET    | `/albums/{id}`        | Инфо об альбоме (ассеты)          |
| PUT    | `/albums/{id}/assets` | Добавить ассеты в альбом          |
| DELETE | `/albums/{id}/assets` | Убрать ассеты из альбома          |
| PATCH  | `/albums/{id}`        | Обновить альбом (название и т.п.) |
| DELETE | `/albums/{id}`        | Удалить альбом                    |

Альбом — коллекция ассетов, может шариться другим пользователям или через shared link.

### 2.4. Shared links (публичные ссылки)

| Метод  | Путь                 | Назначение                                 |
| ------ | -------------------- | ------------------------------------------ |
| POST   | `/shared-links`      | Создать shared link (альбом/набор ассетов) |
| GET    | `/shared-links/me`   | Текущий shared link (по ключу/slug)        |
| GET    | `/shared-links/{id}` | Инфо о ссылке                              |
| PATCH  | `/shared-links/{id}` | Обновить (пароль, запрет скачивания, срок) |
| DELETE | `/shared-links/{id}` | Удалить ссылку                             |

Shared link — публичный URL к альбому/набору без полной авторизации: может иметь пароль,
slug, запрет скачивания (`allowDownload`), срок действия. Просмотр галереи по shared link
не требует API-ключа — но делает фото «публичными по ссылке».

### 2.5. Search (поиск/выбор фото)

| Метод | Путь                   | Назначение                                                |
| ----- | ---------------------- | --------------------------------------------------------- |
| POST  | `/search/metadata`     | Поиск по метаданным (дата, альбом, тип и т.п.), пагинация |
| POST  | `/search/smart`        | Смысловой поиск (CLIP)                                    |
| POST  | `/search/large-assets` | Поиск по большим наборам                                  |
| POST  | `/search/statistics`   | Статистика поиска                                         |
| GET   | `/search/suggestions`  | Подсказки поиска                                          |

`POST /search/metadata` — основной способ «показать фото за период/из альбома» для пикера.

### 2.6. Download

| Метод | Путь                | Назначение                  |
| ----- | ------------------- | --------------------------- |
| POST  | `/download/info`    | Инфо о скачивании набора    |
| POST  | `/download/archive` | Скачать набор архивом (zip) |

## 3. SDK

Immich публикует автогенерированный TypeScript SDK — `@immich/sdk` (npm, oazapfts).
Использование:

```ts
import { getMyUser, init } from '@immich/sdk';

init({ baseUrl: 'https://<host>/api', apiKey: '<API_KEY>' });
const me = await getMyUser();
```

Для нашего бэкенда достаточно прямых `fetch` к API (нет тяжёлой зависимости); SDK — запасной
вариант, если вызовов станет много.

## 4. Варианты интеграции для фото «Дневника»

Как сейчас устроены фото «Дневника»: файлы на диске в `DIARY_IMAGES_DIR` (`server/images/`,
сохраняется при деплое), папка события `evt-…`, ленивое превью (`sharp`, WebP, `?preview=1`),
раздача `GET /api/diary/images/:folder/:file` под авторизацией, в markdown — маркеры
`diary-image://`. Подробно — `docs/specification-diary.md`.

| Вариант                   | Суть                                                                                                                | Плюсы                                                                                   | Минусы                                                                                             |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| **A. Ссылки**             | Событие хранит `immichAssetId`; бэкенд проксирует превью/оригинал из Immich (`/assets/{id}/thumbnail`, `/original`) | Нет дублирования и роста `server/images/`; фото живут в единой медиатеке (дедуп, поиск) | Жёсткая зависимость от доступности Immich; нужен пикер; сетевые задержки (можно кэшировать превью) |
| **B1. Пicer-ссылка**      | В модалке события выбор фото из Immich, вставка ссылок на ассеты                                                    | Точечно, не меняет модель                                                               | Зависимость от Immich                                                                              |
| **B2. Пикер-импорт**      | Выбор фото из Immich (`/search/metadata`), скачивание оригинала (`/original`) в папку события `imageStore`          | Дневник самодостаточен; низкий риск; минимум изменений                                  | Дублирование файлов                                                                                |
| **C. Зеркало**            | При создании события дополнительная загрузка фото в Immich (`/assets`), альбом на событие (`/albums`)               | Резервная копия; фото попадают в общую медиатеку                                        | Дублирование хранилища/трафика; синхронизация удалений                                             |
| **D. Shared link**        | Альбом + shared link на событие, публичная галерея                                                                  | Разгрузка бэкенда, без API-ключа для просмотра                                          | Фото «публичны по ссылке»; меньше контроля                                                         |
| **E. Гибрид (рекоменд.)** | Локальная загрузка остаётся основным путём; Immich — источник при выборе (B2) и/или архив (C)                       | Самодостаточность + удобство медиатеки                                                  | —                                                                                                  |

**Решение (шаг 1):** начать с подключения инстанса — админ-настройки Immich (адрес + API-ключ +
проверка соединения). Дальнейшие шаги (пикер/импорт/зеркало) — отдельные задачи.

## 5. Шаг 1 — админ-настройки подключения к Immich (реализовано)

Цель шага: в админке — форма подключения к инстансу Immich: адрес инстанса, API-ключ,
кнопка «Проверить соединение». При успехе — зелёная галочка возле адреса и сохранение
реквизитов в БД; при ошибке — только красный крест (без сохранения).

### 5.1. Хранение настроек

Общая key-value таблица `settings` в основной БД приложения (`DB_PATH` = `data/vps.sqlite`,
`db/database.ts`; файл сохраняется при деплое как часть `server/data/`). Ключи:

- `immich.baseUrl` — нормализованный адрес API инстанса (с суффиксом `/api`);
- `immich.apiKey` — API-ключ (хранится только в БД, на фронтенд не отдаётся).

Репозиторий — `db/settingsRepository.ts` (`getSetting`/`setSetting`); таблица создаётся
автоматически в схеме `database.ts`.

### 5.2. Сервис подключения — `services/immichService.ts`

- `normalizeImmichBaseUrl(input)` — trim, убирает завершающий `/`, добавляет `/api`,
  если его нет (принимается и голый хост, и адрес с `/api`).
- `testImmichConnection(baseUrl, apiKey)` — `GET <base>/server/about` с заголовком
  `x-api-key`, таймаут (AbortController). 200 → `{ok: true, version: {major, minor, patch}}`;
  401 → «неверный API-ключ»; сетевые ошибки/недоступность → сообщение. Ошибки не бросаются —
  возвращаются структурой `{ok: false, error}`. Версия читается из `/server/about` в обоих
  форматах (объект `serverVersion` / строка `version`); при отсутствии — из публичного
  `/server/version` (запасной источник).

### 5.3. API (монтируется в `app.ts` как `/api/settings`)

`GET` — любому авторизованному (адрес инстанса нужен для ссылок «Фотоархив»/«Архив» в UI);
`POST check` — только роль `admin` (`requireAdmin` в роутере).

| Метод | Путь                         | Доступ               | Назначение                                                    |
| ----- | ---------------------------- | -------------------- | ------------------------------------------------------------- |
| GET   | `/api/settings/immich`       | любой авторизованный | Текущие настройки: `{baseUrl, apiKeyConfigured}` (без ключа!) |
| POST  | `/api/settings/immich/check` | admin                | Проверка соединения; **при успехе сохраняет** реквизиты в БД  |

`POST /api/settings/immich/check`, тело `{baseUrl, apiKey?}`:

- `apiKey` пуст/не задан, но ключ уже сохранён → проверка идёт сохранённым ключом
  (повторная проверка не затирает ключ);
- успех → сохранить `baseUrl` + `apiKey` (если передан) → `{ok: true, version}`;
- ошибка → **не сохранять** → `{ok: false, error}` (HTTP 200 — бизнес-результат проверки,
  не ошибка сервера).

Секьюрити: API-ключ не возвращается клиенту никогда; форма показывает «ключ задан»
(placeholder), пустое поле при сохранении означает «оставить прежний».

### 5.4. Фронтенд — админ-страница «Настройки»

- Маршрут `#/admin/settings` (`ROUTES.adminSettings`), страница `AdminSettingsPage.tsx`
  (ленивый чанк, как `AdminUsersPage`), доступ — только `admin` (`AdminGate`).
- Вход в админку — иконка-шестерёнка (`SettingsIcon`) рядом с бейджем «админ» в шапке
  (`PageLayout.tsx`).
- Форма: поле «Адрес инстанса» (с инлайн-индикатором: зелёная галочка / красный крест
  возле адреса), поле «API-ключ» (type=password; если ключ задан — placeholder,
  пустое значение = оставить прежний), кнопка «Проверить соединение».
- При успехе: зелёная галочка + сообщение «Подключение установлено (версия X.Y.Z)».
  При ошибке: красный крест + сообщение об ошибке. Сохранение происходит на бэкенде
  только при успешной проверке.
- Клиентские функции — `api/client.ts`: `fetchImmichSettings()`, `checkImmichSettings(baseUrl, apiKey?)`.

**Использование адреса в UI (без хардкода):** хук `useImmichSettings()` (`hooks/useImmichSettings.ts`)
читает `GET /api/settings/immich`, убирает суффикс `/api` и возвращает web-адрес инстанса
(кэш на время сессии). По нему формируются ссылки «Фотоархив» (карточка на главной,
`HomePage.tsx`) и «Архив» (футер, `PageLayout.tsx`); обе открываются в новой вкладке
(`target="_blank"` с переключением на неё). Если адрес не задан — ссылки скрываются.
Захардкоженного адреса в коде больше нет.

### 5.5. Критерии приёмки (шаг 1)

1. `GET /api/settings/immich` доступен любому авторизованному (401 без сессии), не возвращает API-ключ.
2. `POST /api/settings/immich/check` с валидными адресом+ключом → `{ok: true, version}`,
   реквизиты сохранены в БД (`settings`).
3. При неверном ключе/недоступном адресе → `{ok: false, error}` (красный крест), БД не меняется.
4. Повторная проверка без ввода ключа (поле пустое) использует сохранённый ключ.
5. UI: зелёная галочка возле адреса при успехе, красный крест при ошибке; страница — только admin.
6. «Фотоархив» (главная) и «Архив» (футер) ведут на адрес из настроек; при пустых настройках
   ссылки скрыты (захардкоженного адреса в коде нет).

## 6. Шаг 2 — пикер-импорт (вариант B2, реализовано)

В форме создания/редактирования события «Дневника» (admin) — кнопка «Из Immich»: выбор фото
из инстанса по диапазону дат съёмки, импорт оригиналов в событие как обычных файлов.
Дневник остаётся самодостаточным (файлы в `server/images/`), Immich — источник при вводе.

### 6.1. Прокси-API (бэкенд, только admin)

Все вызовы Immich идут с бэкенда, API-ключ из настроек клиенту не отдаётся.
Роутер `/api/immich` (`routes/immich.ts`, `controllers/immichController.ts`) монтируется
в `app.ts` под `requireAdmin`.

| Метод | Путь                               | Назначение                                                                                                             |
| ----- | ---------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| GET   | `/api/immich/search`               | Поиск фото (`POST /search/metadata`): диапазон дат съёмки, только изображения, допустимые к импорту (JPG/PNG/WebP/GIF) |
| GET   | `/api/immich/assets/:id/thumbnail` | Миниатюра (`GET /assets/{id}/thumbnail?size=thumbnail`) — прокси потоком                                               |
| GET   | `/api/immich/assets/:id/original`  | Оригинал (`GET /assets/{id}/original`) — прокси потоком                                                                |

Расширение сервиса — `services/immichService.ts`:

- `getImmichCredentials()` — реквизиты из настроек (адрес + ключ), `null` — инстанс не настроен;
- `searchImmichAssets({takenAfter, takenBefore, page, size})` — `POST /search/metadata`
  (`type: IMAGE`, `order: desc`), фильтр по `originalMimeType`/расширению имени файла.
  **Даты передаются с часовым поясом** — Immich валидирует `takenAfter`/`takenBefore` через
  `isoDatetimeToDate` с `offset: true` (без `Z`/смещения запрос отклоняется 400); `nextPage`
  в v3 — строка-токен, нормализуется в число;
- `fetchImmichAssetBinary(id, 'thumbnail'|'original')` — бинарный файл (поток);
- `ImmichError` — ошибка с HTTP-статусом (400 — не настроен, 401 — ключ, 403 — права, 404 — не найден, 502 — апстрим).

### 6.2. Фронтенд

- `components/ImmichPickerModal.tsx` — модалка-пикер: диапазон дат (по умолчанию — даты
  события, если заданы: `defaultFrom`/`defaultTo`; иначе последние 3 месяца), сетка миниатюр
  с мультивыбором, «Показать ещё» (пагинация), кнопка «Добавить N фото» — скачивает оригиналы
  (`fetchImmichOriginal`) и отдаёт `File[]`.
- `DiaryEventModal.tsx` — кнопка «Из Immich» (видна, если инстанс настроен — `useImmichSettings`);
  выбранные файлы вливаются в форму как обычные загрузки (`addFiles`) — обложка, `keep`/`newIds`,
  маркеры `diary-image://` работают без изменений. В пикер передаются даты события
  (`dateStart` → «снято с», `dateEnd` → «по»; без `dateEnd` — один день события).
- `api/client.ts`: `fetchImmichSearchAssets`, `immichThumbnailUrl`, `fetchImmichOriginal`.

### 6.3. Права API-ключа и ограничения

Для шага 2 нужен ключ с правами `server.about`, `asset.read`, `asset.view`, `asset.download`
(см. §1.1). Оригинал больше 10 МБ (лимит формы события) не импортируется — пикер сообщает
об этом; HEIC/RAW скрываются фильтром по MIME.

### 6.4. Критерии приёмки (шаг 2)

1. Кнопка «Из Immich» в форме события видна только при настроенном инстансе и только admin.
2. Пикер показывает фото за выбранный период (миниатюры через прокси), поддерживает выбор и пагинацию.
3. «Добавить N фото» импортирует оригиналы в форму; событие сохраняется как с обычными файлами.
4. Фото больше 10 МБ не импортируются (сообщение), HEIC/RAW скрываются (фильтр по MIME).
5. Без настроенного инстанса/ключа — понятная ошибка, без падения.
