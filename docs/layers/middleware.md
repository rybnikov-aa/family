# Слой Middleware

Документ фиксирует сквозную обработку HTTP-запросов. Модульная бизнес-логика остается в [доменных спецификациях](../domains/), а список маршрутов и схемы ответов — в [API-контракте](api.md).

## Порядок обработки

В `backend/src/app.ts` запрос проходит общие middleware в следующем порядке:

1. CORS с origin из runtime-конфигурации.
2. JSON и URL-encoded body parsers.
3. Публичные `/api/health` и `/api/auth`; доступ к auth-маршрутам дополнительно задается внутри `authRouter`.
4. Защищенные роутеры модулей и их route-level middleware.
5. Общий `notFoundHandler`, затем `errorHandler`.

## Авторизация

Реализация находится в `backend/src/middlewares/auth.ts`; бизнес-модель пользователя и сессии — в [спецификации авторизации](../domains/auth.md).

- `requireAuth` извлекает имя cookie из `AUTH_COOKIE_NAME`, проверяет токен через auth service, записывает пользователя в `req.user`; отсутствующая, истекшая или недействительная сессия дает HTTP 401.
- `requireAdmin` требует роль `admin`; отказ дает HTTP 403. Если `req.user` уже установлен внешним `requireAuth`, повторная проверка сессии не выполняется.
- Публичны `/api/health`, `POST /api/auth/login` и иные явно объявленные public endpoints. `/api/auth/me` и profile требуют сессию; admin endpoints требуют роль admin.
- На уровне монтирования `requireAuth` закрывает VPS, проекты, ремонт, дневник и settings; весь `/api/immich` защищен `requireAdmin`.

Полный endpoint/access matrix — в [API-контракте](api.md); не выводить правила доступа только из UI-гейтов: серверная проверка обязательна.

## Загрузка файлов

Загрузка реализована в `backend/src/middlewares/upload.ts` и `uploadImages.ts` на `multer.memoryStorage()`:

- PDF: поле multipart `file`, максимум 20 MiB; не-PDF отклоняются, превышение размера дает 413, прочие ошибки загрузки — 400.
- Изображения: поле multipart `images`, максимум 30 файлов по 10 MiB каждый; допустимы JPEG, PNG, WebP и GIF по MIME или расширению; превышение размера дает 413, количества или иная ошибка — 400.
- Хранилище и подтверждение загруженного контента принадлежат соответствующим доменным сервисам: [Ремонт](../domains/renovation.md) и [Дневник](../domains/diary.md).

## Ошибки

- `notFoundHandler` возвращает 404 с `{ message }`.
- `errorHandler` логирует неожиданную ошибку и возвращает 500 с нейтральным сообщением.
- Ошибки валидации и конфликтов, которые имеют доменное значение, отображаются контроллерами как 4xx; правила конкретных endpoint описаны в API-контракте.

## Границы ответственности

Middleware выполняет общие проверки/преобразования HTTP-запроса. Не помещать в него доменные расчеты, доступ к конкретным таблицам или UI-политику. Новую глобальную обработку регистрировать в `app.ts`; маршрутные проверки оставлять у соответствующего router/controller.
