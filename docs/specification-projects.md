## 1. Требования

**FR-10. Раздел «Проекты».**

- 10.1 Проект — это подпапка в каталоге `PROJECTS_DIR` (папка проектов) с файлом `index.html`; страницы проекта обслуживаются по `/projects/<slug>/`.
- 10.2 Список проектов динамический: `GET /api/projects` сканирует подпапки `PROJECTS_DIR` и возвращает метаданные (`slug`, `title`, `description`, `accent`, `url`, `order`).
- 10.3 Метаданные берутся из самого `index.html` проекта: `<title>`, `<meta name="project-title">`, `<meta name="description">`, `<meta name="project-accent">`, `<meta name="project-icon">`, `<meta name="project-order">`.
- 10.4 На главной есть карточка «Проекты», ведущая на страницу `#/projects`.
- 10.5 Страница «Проекты» показывает список проектов карточками (иконка по `project-icon`, акцентный цвет из метаданных); карточка — ссылка на страницу проекта (`/projects/<slug>/`). Карточки проектов — широкие (`card--wide`): занимают две колонки сетки (как две обычные карточки).
- 10.6 Страницы проектов наследуют стиль и тему приложения (общий шаблон `projects/`): стили `/projects/styles.css`, тема `/projects/theme.js`, иконки — SVG из `/projects/icon-sprite.svg` (эмодзи как иконки не используются); тема хранится в `localStorage['theme']` (общая для домена) и сохраняется при переходе между приложением и проектами. Переключатель темы на страницах проектов идентичен переключателю приложения: SVG-иконки солнца/луны/монитора (цвета `--toggle-icon-sun/moon/system`), без текстовых подписей.
- 10.7 Проекты деплоятся из папки `projects/` репозитория: она зеркалится 1:1 в `public_html/projects/` — туда попадают и общие файлы проекта (`styles.css`, `theme.js`, `icon-sprite.svg`), и подпапки проектов (например, `renovation/` → `/projects/renovation/`); служебные папки `_*` не деплоятся; существующие подпапки на сервере не удаляются, перезаписываются только записи из репозитория (резервная копия не создаётся).
- 10.8 На странице «Проекты» есть кнопка «Загрузить PDF» (только для роли `admin`): открывает модалку выбора папки на сервере (внутри `PROJECTS_DIR`) и файла PDF. Загрузка — вариант «просто доставка»: файл сохраняется в выбранную папку без автоматического связывания со страницами проекта.
- 10.9 Список папок — `GET /api/projects/dirs` (рекурсивно по `PROJECTS_DIR`, служебные `_*`/`.*` пропускаются); загрузка — `POST /api/projects/upload` (multipart: `folder` + `name` + `file`). Папка создаётся при необходимости; путь проверяется (запрещены абсолютные пути, выход за границы `PROJECTS_DIR` через `..`, служебные папки); имя файла нормализуется (гарантируется `.pdf`); лимит размера 20 МБ → 413, не-PDF → 400.

> Авторизация (весь портал за входом, роли `admin`/`user`) — в [docs/specification-auth.md](specification-auth.md). Загрузка PDF доступна только роли `admin`.

## 2. Сканирование проектов (`services/projectsService.ts`)

- Каталог — `env.PROJECTS_DIR` (по умолчанию `../public_html/projects` относительно каталога бэкенда — папка проектов на сервере).
- Сканируются непосредственные подпапки, содержащие `index.html`; служебные/скрытые (`_*`, `.*`) пропускаются.
- URL проекта — `/projects/<slug>/` (папка проектов обслуживается по `/projects/`; деплой зеркалит `projects/` репозитория в неё 1:1).
- Метаданные из самого `index.html`: `title`/`project-title`, `description`, `project-accent` (по умолчанию `#3b82f6`), `project-icon` (по умолчанию пусто — иконка по умолчанию), `project-order` (по умолчанию — в конец списка).
- Сортировка: по `project-order`, затем по названию (ru).
- Результат кэшируется 60 с.

Формат ответа `GET /api/projects`:

```json
[
  {
    "slug": "renovation",
    "title": "Ремонт",
    "description": "Отчётность по ремонту: смета, внесённые средства, отчёты о работах и материалах.",
    "accent": "#e8872e",
    "url": "/projects/renovation/",
    "order": 0
  }
]
```

## 3. Загрузка PDF на сервер (`services/projectsService.ts`, `middlewares/upload.ts`)

- Список папок — `GET /api/projects/dirs`: рекурсивный обход `PROJECTS_DIR` (без `_*`/`.*`), возвращает относительные пути через `/` (например `renovation/pdf/00 Дизайн-проект`).
- Загрузка — `POST /api/projects/upload` (multipart, поле файла — `file`, `multer` в `middlewares/upload.ts`; доступно роли `admin`):
  - `folder` — относительный путь внутри `PROJECTS_DIR` (создаётся при необходимости); запрещены абсолютные пути, выход за границы (`..`) и служебные папки (`_*`/`.*`);
  - `name` — имя файла (UTF-8, из JS `file.name` — кириллица не «ломается» латиницей, в отличие от `originalname` multer); нормализация гарантирует расширение `.pdf`;
  - лимит размера 20 МБ (`MAX_UPLOAD_SIZE`) → 413, не-PDF → 400;
  - файл сохраняется в `PROJECTS_DIR/<folder>/<имя>.pdf`, ответ — `{url}` (например `/projects/renovation/pdf/00%20Дизайн-проект/файл.pdf`); раздаётся nginx как статика.
- nginx: для загрузки нужен `client_max_body_size 20m` (дефолт 1 МБ).

Инвентарь хуков/компонентов/иконок — в общем разделе [docs/specification.md](specification.md). Относящиеся к модулю:

### Поведение (UX)

- На главной в сетке разделов — карточка «Проекты» (каталог), ведущая на `#/projects`.
- Раздел «Ремонт» на главной убран (переехал в «Проекты»): карточка в сетке, метрика в статусах, кнопка в шапке и ссылка в футере удалены; проект «Ремонт» доступен через «Проекты» и отображается с иконкой-ключом (как у прежнего раздела).
- Страница «Проекты»: заголовок «Проекты» + сетка карточек проектов (иконка по `project-icon`, название, описание, акцентный цвет из метаданных); карточка — ссылка на страницу проекта (`/projects/<slug>/`). Карточки проектов — широкие (`SectionCard` с флагом `wide`, CSS-класс `card--wide`): занимают две колонки сетки, как две обычные карточки.
- Состояния страницы: загрузка («Загрузка проектов…»), ошибка (бэкенд недоступен), пустой список («Проектов пока нет»).
- В шапке и футере приложения — пункт меню «Проекты».

## 6. Критерии приёмки

### 6.1. Раздел «Проекты»

- [ ] В сетке разделов на главной есть карточка «Проекты», ведущая на `#/projects`.
- [ ] В шапке и футере есть пункт «Проекты».
- [ ] Страница «Проекты» показывает список проектов карточками (название, описание, акцентный цвет); карточка — ссылка на страницу проекта (`/projects/<slug>/`).
- [ ] Карточки проектов — широкие (класс `card--wide`): каждая занимает две колонки сетки, как две обычные карточки.
- [ ] Проект «Ремонт» отображается первым в списке (`project-order=0`).
- [ ] Проект «Ремонт» в списке проектов отображается с иконкой-ключом `RenovationIcon` (как был раздел на главной); у прочих проектов — иконка по умолчанию.
- [ ] При недоступном бэкенде страница показывает состояние ошибки (не падает).
- [ ] Страницы проектов наследуют тему приложения: выбор темы (`localStorage['theme']`) сохраняется при переходе приложение ↔ проект; переключатель темы есть и на странице проекта.
- [ ] Иконки на страницах проектов — SVG из `/projects/icon-sprite.svg` (эмодзи как иконки не используются), цвет сохранён от исходной эмодзи.
- [ ] `GET /api/projects` возвращает метаданные проектов из подпапок `PROJECTS_DIR` (новый проект = новая подпапка с `index.html` появляется в списке без пересборки).

## 7. Поведенческие сценарии (Given/When/Then)

**S13. Открытие раздела «Проекты».**

- Given: главная страница портала
- When: пользователь открывает `#/projects` (или кликает карточку «Проекты»)
- Then: отображается список проектов, полученный от `GET /api/projects`; проект «Ремонт» — первым

**S14. Тема сохраняется при переходе в проект.**

- Given: в приложении выбрана тема (например, тёмная), `localStorage['theme']='dark'`
- When: пользователь открывает страницу проекта (например, `/projects/renovation/`)
- Then: страница проекта отрисовывается в той же теме (`data-theme='dark'`); переключение темы на странице проекта меняет тему и в приложении

**S15. Новый проект без правок кода.**

- Given: на сервере в `PROJECTS_DIR` создана подпапка `new-project/` с `index.html` (с мета-тегами)
- When: выполняется `GET /api/projects` (мимо 60-с кэша)
- Then: проект появляется в списке; деплой из репозитория при этом не требуется

## 9. Карта файлов модуля (статичные страницы проектов)

- `projects/theme.js` — тема (light/dark/system) + переключатель для страниц проектов.
- `projects/icon-sprite.svg` — общий SVG-спрайт иконок проектов (цветные — цвет сохранён от эмодзи; бренд `#users` — контурный, наследует `currentColor`).
- `projects/_template/index.html` — шаблон новой страницы проекта (в деплой не попадает).
- `projects/renovation/` — проект «Ремонт» (отчётность, в стиле приложения; публикуется в `/projects/renovation/`):
  - `index.html` — главная страница проекта (общий шаблон проектов + дизайн-система `report.css`); в одной сетке `.cards` — три карточки в стиле карточки проекта: «Дизайн-проект» (ссылки на PDF из папки `pdf/00 Дизайн-проект/`; папка есть только на сервере, в репозиторий не включается и при деплое сохраняется), «Блок 1. Работы» и «Блок 2. Материалы» (итоговая сводка: таблица «Показатель/Комментарий» + сводные карточки `.doc-card.card-stack` (в Блоке 1 — две: «Ход работ» и «Взаиморасчеты» — при достаточной ширине контейнера рядом, на узких экранах столбцом; в Блоке 2 — три); ранее это был отдельный «Итоговый отчёт» `Reports/report_final.html`, теперь файла нет — сводка перенесена на главную); ниже сетки — блок «Примечания» `.note`;
