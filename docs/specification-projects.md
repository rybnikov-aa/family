## 1. Требования

**FR-10. Раздел «Проекты».**

- 10.1 Проект — запись в БД `projects` (созданные через UI, `kind: 'app'`) либо встроенный проект из реестра `backend/src/config/appProjects.ts` (например, «Ремонт», `kind: 'app'`). Статичных подпапок нет: страницы проектов — маршруты приложения (например `#/projects/renovation`, `#/projects/dacha`).
- 10.2 Список проектов динамический: `GET /api/projects` возвращает объединение «встроенный реестр `config/appProjects.ts` + записи БД `projects`» с метаданными (`slug`, `title`, `description`, `accent`, `icon`, `url`, `order`, `kind: 'app'`, `editable`). Сортировка — по `order`, затем по названию (ru). Сканирование файловой системы не выполняется.
- 10.3 Метаданные встроенного проекта — из реестра; созданного через UI — из БД (`title`, `description`, `accent`, `icon`, `order`).
- 10.4 На главной есть карточка «Проекты», ведущая на страницу `#/projects`.
- 10.5 Страница «Проекты» показывает список проектов карточками (иконка по `icon`, акцентный цвет из метаданных). Карточка — внутренний маршрут приложения `url` (например `/projects/renovation` → hash-ссылка `#/projects/renovation`). Карточки проектов — широкие (`card--wide`): занимают две колонки сетки (как две обычные карточки).
- 10.6 Страница созданного проекта (`#/projects/<slug>`) рендерит название, описание и markdown-контент (`content` из БД) в общем стиле приложения. Встроенные проекты («Ремонт») имеют собственную страницу-приложение.
- 10.7 Проекты хранятся в приложении (БД), а не на файловой системе; деплой статичные страницы проектов не зеркалирует. Папка `projects/` репозитория — история (статичный архив «Ремонта» и архивированные навыки `projects/skills-archive/`), seed упразднён (см. спецификацию модуля renovation).
- 10.8 На странице «Проекты» есть кнопка «Создать проект» (только для роли `admin`): открывает модалку создания (slug, название, описание, акцентный цвет, иконка, порядок, markdown-контент). Создание — запись в БД, без правок кода и деплоя.
- 10.9 Создание/изменение/удаление — `POST`/`PATCH`/`DELETE /api/projects` (admin). `slug` — латиница, цифры и дефисы (без `_`/`.` в начале); занятое имя (реестр или БД) → 409; `accent` — `#RRGGBB`, `icon` — `renovation|folder|projects`, `order` — неотрицательное целое. Встроенные проекты (реестр) редактировать/удалять нельзя → 400.

> Авторизация (весь портал за входом, роли `admin`/`user`) — в [docs/specification-auth.md](specification-auth.md). Создание проекта доступно только роли `admin`.

## 2. Хранилище проектов (`services/projectsService.ts`, `db/projectsRepository.ts`)

- Таблица `projects` (SQLite, отдельная БД `data/projects.sqlite`, путь — `PROJECTS_DB_PATH`): `slug` (UNIQUE), `title`, `description`,
  `accent`, `icon`, `order_num`, `content` (markdown), `created_at`, `updated_at`.
- `listProjects()` — встроенный реестр `config/appProjects.ts` (в т.ч. «Ремонт», `editable: false`)
  - записи БД (`editable: true`); сортировка по `order`, затем по названию (ru). Скан файловой
    системы и 60-с кэш отсутствуют (`?refresh=1` принимается для обратной совместимости).
- `getProject(slug)` — полные данные (с `content`); встроенный проект → `content: ''`.
- Создание/обновление/удаление — только для записей БД; конфликт UNIQUE → 409 (`isConstraintError`).

## 3. Создание/изменение/удаление проекта (`services/projectsService.ts`)

- `POST /api/projects` (admin): JSON `{slug, title, description, accent?, icon?, order?, content?}` —
  вставка в БД `projects`. `slug` — латиница, цифры и дефисы (`/^[a-z0-9]+(?:-[a-z0-9]+)*$/`), без
  `_`/`.` в начале; занятое имя (запись реестра или БД) → 409; `title`/`description` — обязательные
  непустые → 400; `accent` — hex `#RRGGBB` (по умолчанию `#3b82f6`), `icon` — `renovation|folder|projects`,
  `order` — неотрицательное целое (по умолчанию — в конец списка), `content` — markdown (по умолчанию '').
  Ответ — метаданные созданного проекта (201).
- `PATCH /api/projects/:slug` (admin): обновляет заданные поля (метаданные и/или `content`);
  встроенный проект (реестр) → 400, не найден → 404. Ответ — полные данные (200).
- `DELETE /api/projects/:slug` (admin): удаляет запись; встроенный → 400, не найден → 404. Ответ 204.
- `GET /api/projects/:slug`: полные данные проекта (с markdown-контентом); 404 — не найден.
- Шаблон `projectsTemplate.ts` и папка `projects/_template` **удалены** — создание идёт в БД,
  без генерации статичных страниц.
- Список — `GET /api/projects` (кэша сканирования нет; `?refresh=1` принимается для совместимости).
- PDF-файлы проекта («Ремонт») — исходный материал для конвертации PDF → HTML (исторический
  поток; конвертация выполнялась Python-библиотеками `pdfplumber`/`PyMuPDF` через навыки
  `parse-pdf` и архивный `project-renovation-update-from-pdf` в `projects/skills-archive/`). Это
  НЕ связано с интерактивным просмотром PDF в приложении: загруженные при импорте PDF
  сохраняются в `RENOVATION_DOCS_DIR` (`server/docs/renovation/`) и просматриваются в браузере
  через pdf.js (`components/PdfViewerModal.tsx`, ссылки «Отчёт №N» в «Ремонте») — подход к
  конвертации/извлечению данных он не меняет.
- **Data-слой «Ремонта» (этапы 1–7 выполнены)** — отчётность проекта `projects/renovation/`
  переносится в отдельную БД `data/renovation.sqlite` (`RENOVATION_DB_PATH`, не путать с `DB_PATH`):
  домен `backend/src/services/renovation/domain/`; наполнение — штатное, через импорт PDF
  (seed-импорт из HTML упразднён). Просмотр — read-API `/api/renovation/*` и страница
  `#/projects/renovation` в приложении. Импорт PDF через `pdfplumber` (этап 3) — в приложении
  (кнопка «Импорт PDF», admin). Применение доп. соглашений (этап 4) — кнопка «Доп. соглашение»
  (admin): дифф по наименованиям → подтверждение → версионирование `current` → `history` +
  новая `current`. Отчёты (этап 5) — по ссылкам «Ход работ»/«Закупка материалов» из БД (открываются
  в модальном окне; план vs факт,
  сводка заказов). Подробно — `docs/specification-renovation.md`.

## 4. API модуля

Полный справочник API и матрица доступа — в [docs/specification-api.md](specification-api.md) (раздел «Проекты»). Эндпоинты модуля:

| Метод  | Путь                  | Назначение                                   | Параметры / ответ                                                                                            |
| ------ | --------------------- | -------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |

## 5. Фронтенд модуля

Инвентарь хуков/компонентов/иконок — в общем разделе [docs/specification.md](specification.md). Относящиеся к модулю:

- **Хуки:** `useProjects` (список проектов для страницы «Проекты»), `useProject` (полные данные одного проекта для `#/projects/:slug`).
- **Компоненты:** `ProjectsPage` (страница «Проекты»; кнопка «Создать проект» + действия «Редактировать»/«Удалить» — только для `admin` и `editable`), `ProjectPage` (страница проекта, рендер markdown-контента), `CreateProjectModal`, `ProjectEditModal` (метаданные + markdown-контент), `SectionCard` (карточка; проп `actions` — кнопки поверх карточки).
- **Утилиты:** `utils/markdown.tsx` (рендерер markdown без внешних зависимостей: заголовки, списки, код, цитаты, ссылки), `utils/projectIcons.tsx` (словарь иконок по `icon`).
- **Иконки:** `ProjectsIcon` (портфель) — страница «Проекты»; иконка конкретного проекта — по `project.icon` (`renovation` → `RenovationIcon`, `folder` → `FolderIcon`, иначе `ProjectsIcon`); `EditIcon`/`TrashIcon` — действия на карточке.
- **Тема:** страницы проектов — это страницы приложения, тему наследуют автоматически.

### Поведение (UX)

- На главной в сетке разделов — карточка «Проекты» (каталог), ведущая на `#/projects`.
- Раздел «Ремонт» на главной убран (переехал в «Проекты»): карточка в сетке, метрика в статусах, кнопка в шапке и ссылка в футере удалены; проект «Ремонт» доступен через «Проекты» и отображается с иконкой-ключом (как у прежнего раздела).
- Страница «Проекты»: заголовок «Проекты» + сетка карточек проектов (иконка по `project.icon`, название, описание, акцентный цвет из метаданных); карточка — внутренняя ссылка на страницу проекта (`#/projects/<slug>`). Карточки проектов — широкие (`SectionCard` с флагом `wide`, CSS-класс `card--wide`): занимают две колонки сетки, как две обычные карточки.
- Страница проекта (`#/projects/<slug>`): заголовок с акцентным цветом + markdown-контент; для `admin` (и `editable`) — кнопка «Редактировать».
- Состояния страницы «Проекты»: загрузка («Загрузка проектов…»), ошибка (бэкенд недоступен), пустой список («Проектов пока нет»).
- В шапке и футере приложения — пункт меню «Проекты».

## 6. Критерии приёмки

### 6.1. Раздел «Проекты»

- [ ] В сетке разделов на главной есть карточка «Проекты», ведущая на `#/projects`.
- [ ] В шапке и футере есть пункт «Проекты».
- [ ] Страница «Проекты» показывает список проектов карточками (название, описание, акцентный цвет); карточка — внутренняя ссылка на страницу проекта (`#/projects/<slug>`).
- [ ] Карточки проектов — широкие (класс `card--wide`): каждая занимает две колонки сетки, как две обычные карточки.
- [ ] Проект «Ремонт» отображается первым в списке (`order=0`) и с иконкой-ключом `RenovationIcon`.
- [ ] У встроенных проектов (реестр, например «Ремонт») на карточке нет кнопок «Редактировать»/«Удалить`; у созданных через UI (`editable`) — есть (admin).
- [ ] При недоступном бэкенде страница показывает состояние ошибки (не падает).
- [ ] Страница проекта (`#/projects/<slug>`) рендерит markdown-контент (заголовки, списки, код, ссылки); при пустом контенте — заглушка «Контент пока не добавлен».
- [ ] `GET /api/projects` возвращает объединение реестра `config/appProjects.ts` и записей БД `projects` (`kind: 'app'`, `editable`); сканирование файловой системы не выполняется.
- [ ] На странице «Проекты» для роли `admin` есть кнопка «Создать проект»: форма (slug, название, описание, акцентный цвет, иконка, порядок, markdown-контент); после создания проект появляется в списке без деплоя.
- [ ] `POST /api/projects` валидирует входные данные (невалидный slug/цвет/иконка/порядок → 400), занятое имя → 409; ответ — метаданные проекта (201).
- [ ] `PATCH /api/projects/:slug` обновляет метаданные и/или контент; встроенный проект → 400; не найден → 404.
- [ ] `DELETE /api/projects/:slug` удаляет запись; встроенный проект → 400; не найден → 404.
- [ ] Новый проект, созданный через UI, не создаёт папок/файлов на сервере и хранится в БД `projects`.

## 7. Поведенческие сценарии (Given/When/Then)

**S13. Открытие раздела «Проекты».**

- Given: главная страница портала
- When: пользователь открывает `#/projects` (или кликает карточку «Проекты»)
- Then: отображается список проектов, полученный от `GET /api/projects`; проект «Ремонт» — первым

**S14. Страница проекта.**

- Given: в списке «Проекты» есть созданный через UI проект (запись БД)
- When: пользователь открывает `#/projects/<slug>` (кликает карточку)
- Then: отображается заголовок проекта с акцентным цветом и markdown-контент; для `admin` — кнопка «Редактировать»

**S15. Новый проект без правок кода.**

- Given: на странице «Проекты» администратор нажимает «Создать проект» и заполняет форму (slug, название, описание, …, markdown-контент)
- When: `POST /api/projects` вставляет запись в БД `projects`; список обновляется
- Then: проект появляется в списке и открывается по `#/projects/<slug>`; никаких файлов/папок на сервере не создаётся, деплой не требуется

## 9. Карта файлов модуля (источник данных «Ремонта»)

- `projects/theme.js` — тема (light/dark/system) + переключатель для страниц проектов.
- `projects/icon-sprite.svg` — общий SVG-спрайт иконок проектов (цветные — цвет сохранён от эмодзи; бренд `#users` — контурный, наследует `currentColor`).
- `projects/renovation/` — статичный архив «Ремонта» (история; на сервер не копируется, `server/renovation-source/` упразднён):
  - `index.html` — главная страница проекта (общий шаблон проектов + дизайн-система `report.css`); в одной сетке `.cards` — три карточки в стиле карточки проекта: «Дизайн-проект» (ссылки на PDF из папки `pdf/00 Дизайн-проект/`; папка есть только на сервере, в репозиторий не включается и при деплое сохраняется), «Блок 1. Работы» и «Блок 2. Материалы» (итоговая сводка: таблица «Показатель/Комментарий» + сводные карточки `.doc-card.card-stack` (в Блоке 1 — две: «Ход работ» и «Взаиморасчеты» — при достаточной ширине контейнера рядом, на узких экранах столбцом; в Блоке 2 — три); ранее это был отдельный «Итоговый отчёт» `Reports/report_final.html`, теперь файла нет — сводка перенесена на главную); ниже сетки — блок «Примечания» `.note`;
  - `estimate_seed.html` — исходная смета (план; никогда не меняется);
  - `estimate.html` — актуальная смета (обновляется при каждом доп. соглашении; разметка строк: обновлённые — синим `row-changed`, новые — жёлтым `row-new`, удалённые в предыдущей версии — красным `row-removed`);
  - `estimate_{yyyy-MM-dd}.html` — исторические копии актуальной сметы (создаются сразу при обновлении сметы по доп. соглашению, дата — из даты доп. соглашения, без перезаписи);
