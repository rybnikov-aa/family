# NFR-002: Доступность и деградация

- **Статус:** действует
- **Область:** пользовательская оболочка и backend health.
- **Источники:** `docs/layers/backend.md`, `docs/layers/frontend.md`, `docs/layers/api.md`.

## Требования

- **NFR-002.1** `GET /api/health` доступен без сессии для проверки процесса и внешнего мониторинга.
- **NFR-002.2** Ошибка или недоступность API должна отображаться как контролируемое loading/error/offline состояние; она не должна превращать ожидаемую сетевую ошибку в подтвержденный успешный результат.
- **NFR-002.3** Неизвестный API route возвращает 404; необработанная серверная ошибка возвращает контролируемый 500 response.
- **NFR-002.4** PDF import использует временный draft и explicit confirmation; отклоненный или истекший draft не должен частично публиковаться как подтвержденный документ.

## Проверка

Проверять публичный health endpoint, auth 401/403 и сценарии error states соответствующих domain specs; отдельно проверять API error contract в `docs/layers/api.md`.
