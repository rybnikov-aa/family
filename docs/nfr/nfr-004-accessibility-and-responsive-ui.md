# NFR-004: Доступность и адаптивность интерфейса

- **Статус:** действует
- **Область:** все интерактивные страницы и модальные окна.
- **Источники:** `docs/layers/design-system.md`, `docs/layers/frontend.md`, domain UI sections.

## Требования

- **NFR-004.1** Кликабельные карточки и пользовательские controls должны быть доступны с клавиатуры и иметь доступное имя там, где визуальной подписи нет.
- **NFR-004.2** Модальные окна должны поддерживать предусмотренные focus/close behaviors; внутренние интерактивные controls не должны случайно активировать карточку-родителя.
- **NFR-004.3** Макеты должны работать в light/dark/system theme и адаптироваться к узким viewport; проверка конкретной правки выполняется по процедуре `docs/layers/design-system.md`.
- **NFR-004.4** Статусы не передаются только цветом: интерфейс дополнительно показывает текстовое значение, подпись или доступное описание согласно компоненту.
- **NFR-004.5** Обычный текст должен иметь контраст не ниже 4.5:1, крупный текст — не ниже 3:1; нетекстовые индикаторы и видимые границы фокуса — не ниже 3:1 к соседнему цвету. Проверяются фактические пары foreground/background во всех темах и на используемых поверхностях.
- **NFR-004.6** Все интерактивные элементы должны иметь различимый `:focus-visible`. Вложенные фоновые диалоги не должны объявляться активными модальными диалогами и не должны оставаться доступными для взаимодействия до активации.

## Проверка

Браузерная проверка структуры, клавиатуры, обеих тем и узкого viewport проводится по `docs/layers/design-system.md`; domain specs задают ожидаемые состояния конкретных страниц. Контраст проверяется по WCAG relative luminance для каждой применяемой пары цветов, а не только для значений токенов по отдельности.
