# Спецификация модуля «Новости» (family)

## 1. Назначение

«Новости» — авторизованная лента публикаций семейного портала. Публикация имеет заголовок,
тег, текст, дату публикации, признак закрепления и изображения-вложения. Данные хранятся
в отдельной SQLite-БД `data/news.sqlite` (`NEWS_DB_PATH`), файлы — в `NEWS_ATTACHMENTS_DIR`.

## 2. Требования

- 15.1 Авторизованный пользователь видит только опубликованные записи (`publishAt <= now`).
- 15.2 Записи сортируются: закреплённые первыми, затем по дате публикации от новых к старым.
- 15.3 Администратор может создавать, редактировать, закреплять и удалять записи.
- 15.4 Администратор может добавлять и удалять изображения-вложения при редактировании.
- 15.5 Пользователь может отметить опубликованную запись прочитанной; отметка хранится отдельно
  для каждой учётной записи.
- 15.6 Администратор видит также будущие и снятые с публикации записи в режиме управления.

## 3. API

- `GET /api/news` — опубликованные новости с `read` для текущего пользователя.
- `GET /api/news/admin` — все новости, только `admin`.
- `POST /api/news` — создание multipart-записи, только `admin`.
- `PATCH /api/news/:id` — изменение multipart-записи, только `admin`.
- `DELETE /api/news/:id` — удаление записи и вложений, только `admin`.
- `POST /api/news/:id/read` — отметить запись прочитанной, любой авторизованный.
- `GET /api/news/attachments/:folder/:file` — защищённое изображение-вложение.

## 4. Критерии приёмки

- [ ] Статический массив новостей удалён из frontend.
- [ ] Публикация по дате, закрепление и сортировка работают одинаково в API и UI.
- [ ] Admin CRUD и загрузка изображений проходят серверную авторизацию.
- [ ] Read-receipt не влияет на состояние других пользователей.
- [ ] Runtime БД и вложения сохраняются при деплое.
