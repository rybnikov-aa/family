# Спецификация глобального поиска (family)

## 1. Назначение

Глобальный поиск помогает авторизованному пользователю быстро находить записи в
разделах «Проекты», «Планы» и «Дневник». Поиск не изменяет данные и не требует
отдельного хранилища или индекса.

## 2. Требования

**FR-15. Глобальный поиск.**

- 15.1 В шапке приложения доступно поле поиска по названию и краткому описанию.
- 15.2 Запрос длиной от 2 до 80 символов ищется без учёта регистра.
- 15.3 Результаты группируются по типу записи и содержат название, краткое
  описание и внутреннюю ссылку.
- 15.4 Результат проекта открывает страницу проекта, задача — страницу планов,
  событие — страницу события дневника.
- 15.5 При пустом результате отображается понятное состояние; запрос сохраняется
  в URL страницы результатов.

## 3. API

`GET /api/search?q=<query>` доступен любому авторизованному пользователю.
Ответ: `{results: SearchResult[]}`, где `kind` имеет значение `project`, `plan`
или `diary`, а `id`, `title`, `description`, `url` и `meta` описывают найденную
запись. Пустой или слишком короткий запрос получает `400`.

## 4. Критерии приёмки

- [ ] Endpoint требует действующую сессию.
- [ ] Поиск находит проекты, задачи и события дневника по названию/описанию.
- [ ] Результаты содержат корректные hash-маршруты приложения.
- [ ] Страница результатов имеет состояния загрузки, ошибки и пустого результата.
