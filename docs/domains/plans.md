# Спецификация модуля «Планы» (family)

## 1. Назначение

«Планы» — авторизованный раздел для семейных задач и небольших планов. Задачи
хранятся в отдельной SQLite-БД `data/plans.sqlite` (`PLANS_DB_PATH`).

## 2. Требования

**FR-14. Раздел «Планы».**

- 14.1 Авторизованный пользователь видит список задач, отсортированный по статусу,
  сроку и дате создания.
- 14.2 Задача содержит название, описание, статус (`todo`, `doing`, `done`),
  приоритет (`low`, `normal`, `high`), необязательный срок и необязательную
  привязку к проекту.
- 14.3 Администратор может создать, изменить и удалить задачу.
- 14.4 Форма задачи валидирует непустое название, допустимые статус/приоритет,
  корректную дату и существующий проект при выборе проекта.
- 14.5 На странице отображаются отдельные списки «К выполнению», «В работе» и
  «Готово»; пользователь может фильтровать задачи по проекту и приоритету.
- 14.6 Карточка «Планы» на главной ведёт на `#/plans`.
- 14.7 Задача может иметь повторение `none`, `daily`, `weekly` или `monthly`; у повторяющейся
  задачи после завершения срок сдвигается на следующий период, а статус возвращается в `todo`.
- 14.8 Пользователь переключает списочный и календарный режимы; фильтры проекта и приоритета
  работают в обоих режимах.
- 14.9 Просроченные задачи выделяются, а browser reminders могут уведомить пользователя при
  открытом приложении о ближайшем сроке или просрочке.

## 3. API

- `GET /api/plans` — список задач для любого авторизованного пользователя.
- `POST /api/plans` — создание задачи, только `admin`.
- `PATCH /api/plans/:id` — изменение задачи, только `admin`.
- `DELETE /api/plans/:id` — удаление задачи, только `admin`.

Тело создания/изменения: `{title, description?, status?, priority?, dueDate?, projectSlug?, recurrence?}`.
Ответ задачи содержит `id`, `title`, `description`, `status`, `priority`, `dueDate`,
`projectSlug`, `projectTitle`, `recurrence`, `createdAt`, `updatedAt`.

## 4. Критерии приёмки

- [ ] `/api/plans` защищён авторизацией; мутации требуют роль `admin`.
- [ ] Задачи сохраняются в `data/plans.sqlite` и переживают перезапуск.
- [ ] Некорректные данные получают `400`, отсутствующая задача — `404`.
- [ ] Страница `#/plans` показывает три статусные группы, фильтры и состояния
      загрузки/ошибки/пустого списка.
- [ ] Администратор может выполнить полный CRUD из UI.
- [ ] Пользователь без роли `admin` не видит действий изменения и удаления.
