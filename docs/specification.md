# Спецификация Family

| Поле | Значение |
| --- | --- |
| Тип документа | Общая спецификация и индекс архитектуры |
| Проект | Семейный портал `family` (`frontend` + `backend`) |
| Статус | Актуальная точка входа; поведение уточняется в layer/domain спецификациях |

## Назначение и границы

Этот документ задает карту спецификаций, общие архитектурные положения и правила их владения. Он не дублирует детальные требования, API-таблицы или инвентари файлов.

- **Спецификации слоев** описывают поперечные архитектурные правила и ответственность технических слоев.
- **Спецификации доменов** описывают поведение продукта, данные, требования и критерии приемки функциональных областей.
- **API-спецификация** описывает общий HTTP-контракт и матрицу доступа между клиентом и сервером.
- **Смежные документы** распределены по назначению: внешние сервисы — `docs/integrations/`, эксплуатационные runbooks — `docs/operations/`, внешние ценовые и модельные правила — `docs/policies/`.

## Общие положения

- Приложение — монорепозиторий на React 19, TypeScript, Vite, Node.js и Express 5. Подробная схема слоев — в соответствующих layer-документах.
- Весь портал требует аутентификации, кроме публичных health/login endpoints. Точная матрица доступа задана в [API-спецификации](layers/api.md), реализация сквозной проверки — в [middleware-спецификации](layers/middleware.md).
- Хранилища, конфигурация окружения и runtime-данные описаны на уровне backend и соответствующих доменов; домен владеет поведением своих данных.
- Критерии приемки поведения находятся в доменной спецификации. Для изменений, затрагивающих несколько слоев или HTTP-контракт, синхронно обновляются соответствующие layer/API-документы.

## Правило изменения спецификаций

1. До изменения кода зафиксировать ожидаемое поведение и проверяемые критерии приемки в Git-документе-владельце. Для пользовательского поведения это соответствующая спецификация в `docs/domains/`; если нужных критериев нет, сначала добавить их туда.
2. Изменение общесистемной архитектуры или сквозной инфраструктуры отражается в соответствующей спецификации `docs/layers/`.
3. Изменение endpoint, доступа или формата обмена отражается в `docs/layers/api.md` и затронутых domain-документах.
4. Обновляй этот индекс только при изменении карты документов или общих положений.
5. Код принимается по критериям приемки его доменной спецификации; фактически измененные документы перечисляются в итоговом сообщении.
