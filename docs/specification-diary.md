## 1. Требования

**FR-12. Раздел «Дневник»** (события семьи).

- 12.1 В разделе «Дневник» события отображаются в виде блоков. Событие — запись в отдельной БД
  `data/diary.sqlite` (путь — `DIARY_DB_PATH`); изображения события — на диске в уникальной подпапке
  `images/<folder>/` каталога `DIARY_IMAGES_DIR` (dev — `backend/images/`, сервер — `server/images/`,
  каталог сохраняется при деплое).
- 12.2 Пользователь переключает макет отображения кнопками с иконками (без подписей):
  «список» (на всю ширину) и «карточки» (сетка на 3 столбца). По умолчанию — «список». Переключение
  доступно любому авторизованному пользователю.
- 12.3 Содержимое блока события: изображение (обложка; при отсутствии — заглушка-иконка), название
  события (заголовок), дата (или период дат) в pill, краткое описание. Если дат две — в pill
  отображается «дата1 – дата2».
- 12.4 Пользователь с ролью `admin` может добавить событие кнопкой «+». Форма добавления содержит:
  загрузку фотографий (несколько), выбор основной фотографии, название события, дату (период дат),
  краткое описание, подробное описание в формате markdown.
- 12.5 Клик по блоку открывает отдельную страницу события (`#/diary/:id`), на которой выводятся все
  данные: обложка, название, дата (pill), краткое описание, подробное описание (markdown) и галерея
  прикреплённых фотографий. Фотографии, вставленные в описание, показываются в макете сетки на
  2 столбца и не повторяются в галерее. Галерея остальных фотографий (сетка на 4 столбца) имеет
  ту же ширину, что и блок с фотографиями описания, и отделяется от описания линией.
- 12.9 При создании и редактировании администратор может вставить в Markdown фотографию из уже
  загруженных в событие. Формат внутреннего маркера — `![подпись](diary-image://имя-файла)`;
  при вставке сразу после маркера добавляется перенос строки для последовательного размещения фото.
  Временные id новых файлов заменяются сервером после сохранения. При удалении маркеров из текста
  фотографии возвращаются в список доступных для вставки.
- 12.6 Пользователь с ролью `admin` может отредактировать событие кнопкой «карандашик» (на блоке и
  на странице события) и удалить его (кнопка-корзина с подтверждением; удаляет запись БД и папку
  изображений).
- 12.7 События хранятся в отдельной базе данных (не `DB_PATH`/`AUTH_DB_PATH`/`PROJECTS_DB_PATH`/
  `RENOVATION_DB_PATH`): своя БД `data/diary.sqlite`.
- 12.8 Изображения сохраняются на сервере в папке `server/images/<folder>/`, где `<folder>` —
  уникальное имя папки, генерируемое для каждого события (`evt-<time36>-<hex>`). Раздача —
  `GET /api/diary/images/:folder/:file` (под авторизацией, защита от path traversal).

> Авторизация (весь портал за входом, роли `admin`/`user`) — в [docs/specification-auth.md](specification-auth.md).
> Мутации «Дневника» доступны только роли `admin`.

## 2. Хранилище событий (`db/diaryDatabase.ts`, `db/diaryRepository.ts`, `services/diaryService.ts`)

- Таблица `diary_events` (SQLite, отдельная БД `data/diary.sqlite`, путь — `DIARY_DB_PATH`):
  `id`, `title`, `date_start` (ГГГГ-ММ-ДД), `date_end` (ГГГГ-ММ-ДД, nullable), `summary` (краткое
  описание), `content` (markdown, включая маркеры `diary-image://`), `folder` (уникальная папка изображений), `cover` (имя файла
  основной фотографии), `created_at`, `updated_at`.
- Сортировка списка — по `date_start` (свежие раньше), затем по `id` (свежее созданное раньше).
- `listDiaryEvents()` — сводки (без `content`; `images[]` содержит все изображения события);
  `getDiaryEvent(id)` — полные данные (с `content`; `images[]` — все изображения события);
  обложка по умолчанию — первое изображение (если `cover` не задан или указывает на отсутствующий файл).
- `createDiaryEvent(upload)` / `updateDiaryEvent(id, upload)` / `deleteDiaryEvent(id)` — создание,
  обновление и удаление (удаление также убирает папку изображений события).
- Валидация: `title`/`summary` — непустые; `date_start`/`date_end` — формат ГГГГ-ММ-ДД
  (`/^\d{4}-\d{2}-\d{2}$/` + реальная дата); `date_end < date_start` → 400.

### 2.1. Хранение изображений (`services/diary/imageStore.ts`)

- Каталог — `DIARY_IMAGES_DIR` (по умолчанию `images` относительно CWD бэкенда; на сервере —
  `server/images`, сохраняется при деплое, как `data/` и `docs/`).
- Уникальная папка события — `newEventFolder()` (`evt-<time36>-<hex>`); имена файлов —
  `imageFileName()` (случайные, с сохранением расширения, только `[a-z0-9._-]`).
- `listEventImages(folder)` — список файлов папки события (подпапка `thumbs/` не входит);
  `saveEventImage`/`removeEventImage`/`removeEventImages` — запись/удаление (удаление файла
  убирает и его превью); `resolveEventImage(folder, file)` — безопасный абсолютный путь
  (проверка `[a-z0-9._-]` и выхода за каталог — защита от path traversal).
- **Превью (оптимизация отдачи):** для каждого изображения — уменьшенная копия в подпапке
  `thumbs/<file>` (WebP, максимум `PREVIEW_MAX_SIZE` = 1200 px по большей стороне, качество 82).
  Генерируется лениво при первом запросе `?preview=1` (`ensurePreview`): in-flight дедупликация
  параллельных запросов, атомарная запись (временный файл + rename — недозаписанные файлы
  не отдаются), далее кэшируется на диске. Полный размер в максимальном качестве отдаётся
  только при открытии изображения на весь экран (без `?preview=1`).
- Раздача — `GET /api/diary/images/:folder/:file` (под авторизацией); превью отдаётся с
  `Cache-Control: private, max-age=31536000, immutable` (имя файла неизменяемо).

## 3. Создание/изменение/удаление события (`services/diaryService.ts`)

- `POST /api/diary` (admin, multipart): текстовые поля (`title`, `dateStart`, `dateEnd?`, `summary`,
  `content`, маркеры `diary-image://<new-id>` для новых файлов) + `images` (файлы, поле `images`, до 30 шт., до 10 МБ каждый) + `keep` (JSON-массив
  имён сохраняемых файлов; для создания — пустой) + `newIds` (JSON-массив клиентских id новых
  файлов, длина = числу `images`) + `cover` (клиентский id нового файла либо имя существующего).
  Генерируется уникальная папка, файлы сохраняются, обложка по умолчанию — первое изображение.
  Ответ — полное событие (201); при ошибке сохранения папка удаляется (откат).
- `PATCH /api/diary/:id` (admin, multipart): обновляет поля и синхронизирует изображения — файлы,
  не входящие в `keep`, удаляются с диска, новые добавляются, `cover` обновляется (должен быть одним
  из итоговых изображений, иначе 400). Маркеры фотографий в `content` проверяются относительно
  итоговых изображений. 404 — событие не найдено.
- `DELETE /api/diary/:id` (admin): удаляет запись БД и папку изображений события. 204; 404 — не найдено.
- `GET /api/diary` — список сводок; `GET /api/diary/:id` — полное событие (404 — не найдено).
- Загрузка — `multer` (memory storage), фильтр — изображения (JPG/PNG/WebP/GIF по MIME или
  расширению); превышение размера → 413, число файлов → 400, не-изображение → 400.
- **Добавление фото из Immich (вариант B2):** в форме события (admin) кнопка «Из Immich»
  (видна, если инстанс настроен) открывает пикер — выбор фото по диапазону дат съёмки,
  импорт оригиналов как обычных файлов (через прокси `/api/immich/*`; детали — `docs/immich.md`,
  шаг 2). Импортированные фото участвуют в том же конвейере (обложка, `keep`/`newIds`,
  маркеры `diary-image://`); файлы > 10 МБ не импортируются, HEIC/RAW скрываются.

## 4. API модуля

Полный справочник API и матрица доступа — в [docs/specification-api.md](specification-api.md)
(раздел «Дневник»). Эндпоинты модуля:

| Метод  | Путь                              | Назначение                                   | Параметры / ответ                                                                                                                                                                                        |
| ------ | --------------------------------- | -------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GET    | `/api/diary`                      | Список событий (сводки, без контента)        | 200 — массив `DiaryEventSummary`                                                                                                                                                                         |
| GET    | `/api/diary/:id`                  | Полные данные события (с markdown-контентом) | 200 — `DiaryEventDetail`; 404 — не найдено                                                                                                                                                               |
| POST   | `/api/diary` (admin)              | Создание события                             | multipart: `title`, `dateStart`, `dateEnd?`, `summary`, `content`, `images` (файлы), `newIds` (JSON), `keep` (JSON), `cover`; 201; 400/413                                                               |
| PATCH  | `/api/diary/:id` (admin)          | Обновление события                           | multipart: те же поля; 200; 400/413; 404 — не найдено                                                                                                                                                    |
| DELETE | `/api/diary/:id` (admin)          | Удаление события (+ папка изображений)       | 204; 404 — не найдено                                                                                                                                                                                    |
| GET    | `/api/diary/images/:folder/:file` | Изображение события из `images/<folder>/`    | Без параметра — оригинал в полном размере; `?preview=1` — уменьшенная копия (WebP, подпапка `thumbs/`, генерируется лениво, кэш `immutable`); 400 — некорректный путь (path traversal); 404 — не найдено |

## 5. Фронтенд

- Страница списка — `pages/DiaryPage.tsx` (`#/diary`): шапка с иконкой «Дневника», переключатель
  макета (кнопки с иконками «список»/«карточки», по умолчанию «список»), кнопка «+» (admin).
- Блок события — `components/DiaryEventCard.tsx` (варианты `list`/`cards`); клик — ссылка
  `#/diary/:id`; действия admin (карандаш/корзина) — поверх блока, вне ссылки (`stopPropagation`).
- Страница события — `pages/DiaryEventPage.tsx` (`#/diary/:id`): обложка, название, дата (pill),
  краткое описание, markdown-контент (`utils/markdown.tsx`) с фотографиями в макете сетки на
  2 столбца, галерея оставшихся фотографий (сетка на 4 столбца той же ширины, отделена от описания
  линией-разделителем; ссылки на полный размер). Редактирование — кнопка «карандашик» (admin).
- Форма добавления/редактирования — `components/DiaryEventModal.tsx`: загрузка нескольких фото
  (превью через object URL), выбор любой фотографии в качестве обложки кликом по превью,
  название, период дат (`<input type="date">`), краткое описание, markdown; инструмент вставки
  показывает фотографии миниатюрами с подписями «Фото N», вставляет маркеры `diary-image://...` с
  переносом строки в позицию курсора и скрывает уже вставленные фотографии из списка выбора (при
  удалении маркеров из текста фото возвращаются в список выбора). Все загруженные фотографии остаются
  в общем списке формы и сохраняются при редактировании. Сборка multipart — `buildDiaryFormData()` в `api/client.ts`.
- Хуки: `hooks/useDiaryEvents.ts` (список), `hooks/useDiaryEvent.ts` (деталь, перезагрузка при смене id).
- Стили — `styles/diary.css` (импортируется в `index.css`). URL изображения —
  `diaryImageUrl(folder, file, preview)` в `api/client.ts`: `preview=true` — уменьшенная копия
  (`?preview=1`) для карточек/обложки/галереи/формы; полный размер — только в ссылке «Открыть
  в полном размере» (галерея события, открытие изображения на весь экран).
- Навигация: карточка «Дневник» на главной, пункт «Дневник» в шапке и в футере ведут на `#/diary`.
